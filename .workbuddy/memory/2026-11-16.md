## program_serial_number 回读失败（hero_final_assembly.cs, Linux 树莓派侧）
- 现象: readback mismatch, got='eeprog -qf /dev/i2c-1 ... ; e' —— got 就是命令回显本身, 在回显里的 "readback_done" 处被截断。
- 根因: 串口终端会回显命令, 命令里的 `; echo readback_done` 使标记字面量出现在回显中, IndexOf 取第一个出现 → 命中回显 → SN 和真正的标记全被截掉。TTY 回显状态决定成败, 所以"容易出错"。
- 修复(引号拼接技巧): `echo readback'_done'` → 回显为 readback'_done' 不含字面量, 实际输出仍是 readback_done。三处标记都改: seed_done / sn_written / readback_done; 顺带修正回读命令多余 -f: `eeprog -qf /dev/i2c-N {addr} -8 -r 0x20:12`。
- 同类 bug 一并修复: rtc_check (RTC_BEGIN/RTC_END → RTC'_BEGIN'/RTC'_END', 原代码窗口截到 echo 之间必然解析失败); wifi_scan (WS_BEGIN/WS_END → WS'_BEGIN'/WS'_END', 原注释想用 LastIndexOf 避开回显但全流只有回显一次出现, 无效)。
- 无需修改: sync_done(仅等提示符)、RELAY_SET_DONE(未参与解析)。
- usb_storage_check 失败: sproj/代码等待字面量 "USB Storage", 但内核消息是 "usb-storage ...: USB Mass Storage device detected" (usb-storage 带连字符, grep -i 也匹配不上带空格的 "USB Storage") → 必超时。修复: 代码默认值与 Hero_Final_Assembly_Test.sproj 参数均改为 "Mass Storage device detected" (备份 .sproj.bak1)。
- usb_storage_check 第二轮: 目标机 exe 已更新但 sproj 还是旧参数 text=USB Storage → 仍超时。改为代码兼容: 参数 == "USB Storage" 时自动映射特征组 ["Mass Storage device detected", "Attached SCSI removable disk"], 串口与 dmesg(grep -iE 交替) 双路径都按特征组匹配, 旧 sproj 无需同步即可工作。
- usb_storage_check 第三轮(用户发现): 作业员"先插 U 盘再按 OK"时, 内核枚举消息在弹窗期间到达, 而 mark=rx_mark() 取在弹窗之后 → rx_since(mark) 漏掉插入事件 → 串口路径必超时("先点掉窗再插盘"能用反证了时机问题)。修复: mark 移到 HeroPromptForm.Show 之前取。
